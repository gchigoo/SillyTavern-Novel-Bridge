# SillyTavern Novel Bridge · 长篇小说记忆

为 SillyTavern 提供作者可控的长篇小说记忆：作者设定、逐章状态、历史检索和最近章节摘要。PostgreSQL 保存定稿原文与修订历史，Hindsight 提供记忆检索。浏览器不保存服务端 API key。

## 安装

在 SillyTavern 中打开 **扩展 → 安装扩展**，粘贴：

```text
https://github.com/gchigoo/SillyTavern-Novel-Bridge
```

安装后刷新页面，在扩展设置找到 **长篇小说记忆**。推荐 SillyTavern 1.19.0 或以上；本仓库已针对 1.19.0 验证接口。仓库根目录就是可安装的前端扩展。

**需要配套 Bridge 后端。** 前端访问当前酒馆域名下的 `/novel-bridge/api`。后端与 Hindsight 已配置的站点可以直接安装；仅安装前端不会自动部署 PostgreSQL 或 Hindsight。后端源码和部署说明在 [server/](server/README.md)。

## 写作流程

打开聊天，新建或选择小说，启用当前聊天的小说记忆，填写作者设定、章节编号和本章大纲。

1. **召回记忆**：预览设定、已确认状态、最近两章摘要，以及附章节/版本出处的检索事实。
2. **生成章节**：使用酒馆当前连接的写作模型。已有编辑草稿不会被自动覆盖。
3. **一致性检查**：模型提出摘要和状态变化，作者可以修改，也可以完全手动填写。
4. **确认定稿**：确认后保存正文版本、摘要和状态变化，并排队写入 Hindsight。

只有“确认定稿”会产生章节记忆。普通聊天、重抽、草稿编辑和一致性检查都不会自动定稿。改写早期定稿会标记后续章节待复核；修改设定会标记已有章节待复核。按顺序载入、审阅并重新确认即可。

设定草稿与服务器版本冲突时，先复制需要保留的改动，再使用“载入服务器设定”，合并后保存。加载和保存期间设定框会暂时只读。

状态变化示例：

```json
[{"entity":"林岚","field":"位置","value":"白塔","evidence":"林岚走进白塔"}]
```

`value: null` 表示删除字段。故事时间保持作者输入的原文标签。每部小说独立存储，召回只接受目标章节之前、当前有效版本的定稿事实。

同步任务只有收到 Hindsight 的 `completed` 才显示成功。网络故障保留操作编号重试；定稿原文保存在 SQL 中。早期版本同步失败会阻止同章较新版本覆盖，请先重试较早任务。召回失败会停止启用本扩展的生成；可明确关闭当前聊天的记忆功能继续写作。

## 验证与边界

领域及界面辅助函数、真实 PostgreSQL/HTTP 替身集成、真实 Hindsight/模型接口生命周期均经过验证。浏览器隔离测试覆盖设定加载、保存回执丢失、冲突恢复、保存与刷新竞争，以及生成完成后的预算提示。

模型提取与一致性检查仍需要作者审阅。尚未以数千章真实作品做长期负载测试。
