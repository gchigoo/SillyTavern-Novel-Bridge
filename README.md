# SillyTavern Novel Bridge · 长篇小说记忆

为 SillyTavern 提供聊天记忆仓库。ST 继续使用当前角色卡、世界书、预设和写作模型；插件自动召回历史，再把完成的回复和后续修订同步到记忆。PostgreSQL 保存消息版本，Hindsight 提供检索。浏览器不保存服务端 API key。原有的手动章节工作台仍可使用。

## 安装

在 SillyTavern 中打开 **扩展 → 安装扩展**，粘贴：

```text
https://github.com/gchigoo/SillyTavern-Novel-Bridge
```

安装后刷新页面，在扩展设置找到 **长篇小说记忆**。推荐 SillyTavern 1.19.0 或以上；本仓库已针对 1.19.0 验证接口。仓库根目录就是可安装的前端扩展。

**需要配套 Bridge 后端。** 前端访问当前酒馆域名下的 `/novel-bridge/api`。后端与 Hindsight 已配置的站点可以直接安装；仅安装前端不会自动部署 PostgreSQL 或 Hindsight。后端源码和部署说明在 [server/](server/README.md)。

## 自动聊天记忆（0.2）

前端和 Bridge 后端都需要升级到 0.2。打开一个聊天，在 **长篇小说记忆** 中勾选 **当前聊天启用自动记忆**，然后照常在 ST 输入和发送续写提示。首次启用会同步当前聊天已有的用户与角色消息。

- **生成前召回**：用最近对话与当前输入查询历史，注入辅助资料。角色卡、世界书及当前原文优先；插件不替换 ST 的生成流程，也不需要模型支持工具调用。历史记忆最多占当前上下文的 20%，且不超过 3000 tokens。
- **回复完成后保存**：完整回复自动保存并排队索引。流式停止、异常回复和可识别的未完成生成不会自动入库；编辑半截回复后可将修订文本纳入记忆。
- **随聊天修订**：编辑、重生成、切换回复或删除后，只召回当前选中版本。旧版本先退出召回范围，后台再替换或删除索引；不会等待索引完成才停用旧事实。SQL 和导出仍保留历史修订，删除聊天消息不等于清除备份。
- **聊天隔离**：每个聊天独立建库；复制/分支聊天使用独立库，不带入另一条分支的后续情节。聊天重命名也会建立新库并重新同步当前内容。

面板提供 **同步并查看状态**、**重试失败任务** 和本次召回预览。新消息在索引完成之前仍由 ST 的原始聊天上下文提供；界面会提示尚未完成索引的数量。网络错误不会删除聊天原文，后续同步可恢复；召回或版本校验失败时暂停本次生成，可重试或明确关闭自动记忆后继续。两个设备同时修改同一聊天若发生版本冲突，需要重新载入聊天后再同步。

生成前会通过 ST 的聊天接口回读保存标记。若 ST 因保存繁忙或网络错误未真正写入聊天，插件会暂停生成并提示重试，避免刷新页面后把未完成回复误认作完整消息。群聊切换发言成员、单聊更换头像文件名不会更换同一个聊天的记忆库。

自动模式不额外调用一个缺少完整角色卡/世界书上下文的“审稿模型”。写作模型在 ST 的完整提示下结合召回资料保持连续性；模型提取记忆和遵循设定的准确性仍有局限。仅同步当前显示的文字消息，不将隐藏推理、工具调用、附件或展开后的世界书提示存入记忆。每个聊天最多 10000 条消息，单条正文最多 250000 字符。

## 手动章节工作台

展开 **手动章节工作台（可选）**。启用手动章节记忆会关闭自动模式，两者不会同时注入记忆。

打开聊天，新建或选择小说，启用当前聊天的小说记忆，填写作者设定、章节编号和本章大纲。

1. **召回记忆**：预览设定、已确认状态、最近两章摘要，以及附章节/版本出处的检索事实。
2. **生成章节**：使用酒馆当前连接的写作模型。已有编辑草稿不会被自动覆盖。
3. **一致性检查**：模型提出摘要和状态变化，作者可以修改，也可以完全手动填写。
4. **确认定稿**：确认后保存正文版本、摘要和状态变化，并排队写入 Hindsight。

手动模式下，只有“确认定稿”会产生章节记忆。普通聊天、重抽、草稿编辑和一致性检查都不会自动定稿。改写早期定稿会标记后续章节待复核；修改设定会标记已有章节待复核。按顺序载入、审阅并重新确认即可。

设定草稿与服务器版本冲突时，先复制需要保留的改动，再使用“载入服务器设定”，合并后保存。加载和保存期间设定框会暂时只读。

状态变化示例：

```json
[{"entity":"林岚","field":"位置","value":"白塔","evidence":"林岚走进白塔"}]
```

`value: null` 表示删除字段。故事时间保持作者输入的原文标签。每部小说独立存储，召回只接受目标章节之前、当前有效版本的定稿事实。

同步任务只有收到 Hindsight 的 `completed` 才显示成功。网络故障保留操作编号重试；定稿原文保存在 SQL 中。早期版本同步失败会阻止同章较新版本覆盖，请先重试较早任务。召回失败会停止启用本扩展的生成；可明确关闭当前聊天的记忆功能继续写作。

## 验证与边界

自动模式有消息生命周期测试及真实 PostgreSQL + HTTP 替身集成测试，覆盖编辑/切换/删除、未完成流、恢复、跨聊天响应、并发版本冲突、来源过滤、丢失回执、事务回滚和 worker 顺序。隔离 Chrome 使用实际插件模块验证面板、模式互斥、ST 事件接线及同步预览。测试命令见 [server/](server/README.md)。这些测试不等于任意 ST 版本、第三方扩展组合或线上真实聊天的验证。

模型提取与一致性检查仍需要作者审阅。尚未以数千章真实作品做长期负载测试。
